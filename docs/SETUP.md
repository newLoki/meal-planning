# Setup (one time)

Two things to set up: the **GitHub repo + Pages** (hosts the recipe pages), and the
**Gemini Gem** (produces the plan). Budget ~15 minutes.

---

## Part 1 — GitHub repository & Pages

1. **Create a public repo.** On GitHub: *New repository* → give it a name (e.g.
   `meal-plans`) → **Public** (Bring fetches an anonymous URL; a meal plan isn't
   sensitive) → Create.

2. **Push these files** to the `main` branch. Either upload the unzipped folder via
   *Add file → Upload files*, or from a terminal:
   ```bash
   git init
   git add .
   git commit -m "Recipe-site pipeline"
   git branch -M main
   git remote add origin https://github.com/<owner>/<repo>.git
   git push -u origin main
   ```

3. **Trigger the first build.** The push already triggers the workflow in
   `.github/workflows/build.yml`; otherwise go to **Actions → "Build & deploy recipe
   site" → Run workflow**. It renders the site and pushes it to a `gh-pages` branch.
   Wait for it to go green (this also creates the `gh-pages` branch).

4. **Enable Pages from the branch.** Repo **Settings → Pages → Build and deployment →
   Source: Deploy from a branch → Branch: `gh-pages` / `(root)`** → Save. The built
   site is stored durably on that branch, so older weeks persist across runs; the
   workflow rebuilds only the current + previous week (plus any changed week) by
   default and leaves the rest in place. After Pages finishes deploying, your site is
   live at:
   ```
   https://<owner>.github.io/<repo>/
   ```
   Open it — the bundled example plan (`plans/2026-W29.json`) should show one week
   with three recipes.

5. **(Optional) Custom domain.** Add a repo **Variable** named `PAGES_BASE_URL`
   (Settings → Secrets and variables → Actions → *Variables* tab) set to your domain,
   and add a `CNAME` file. Skip this for the default `*.github.io` URL — the base URL
   is derived automatically from the repo.

That's the host done. Nothing here needs touching again week to week.

---

## Part 2 — The Gemini Gem

1. Go to **gemini.google.com**. In the left sidebar click **Explore Gems**, then
   **New Gem** (also reachable from the profile menu → *Gems* → *New Gem*).
   > Gem creation may require a paid Gemini tier depending on your plan/region.

2. **Name** it (e.g. `GF Meal Planner`).

3. **Instructions:** open `GEMINI_GEM.md` from this repo and paste its entire
   contents into the Instructions box.

4. **Edit one line.** In the pasted instructions, set:
   ```
   SITE_BASE_URL: https://<owner>.github.io/<repo>
   ```
   to your actual Pages URL from Part 1. This is only used so the Gem can print the
   correct recipe links; the buttons themselves are generated by the pipeline.

5. On the right, enter a test prompt (e.g. *"Plan Friday to Tuesday"*) to preview,
   then click **Save**. (Previewing does **not** save — you must click Save.)

---

## Part 3 — Google Calendar (only if you want auto-created events)

The Gem's Phase 3C creates calendar events through Gemini's Google Workspace
integration. For that to work:

1. In Gemini, ensure the **Google Workspace** connection / Calendar extension is
   enabled for your account (Gemini will prompt to connect if it isn't).
2. The Gem must run on the Google account whose calendar you want to write to.

If you'd rather not connect Calendar, ignore Phase 3C — the Gem still produces the
plan JSON and the shopping list. Note that Gemini's time arithmetic can be
inconsistent; the Gem's instructions include worked examples specifically to make
the "start = 19:30 − (prep + cook)" calculation reliable, but sanity-check the first
few events.

## Verify once: the Bring import smoke test

Before trusting it weekly, confirm Bring parses a page correctly (the Bring guide
documents the HTML format fully but not the JSON schema, so this one check matters):

1. On a phone with **Bring! installed**, open any recipe page from your live site.
2. Tap **🛒 Zu Bring! hinzufügen**.
3. Check that **all ingredients** appear, and that the quantity is **for 2, not
   doubled**.

If quantities come out doubled, Bring ignored `recipeYield`; open `render.py`, set
`baseQuantity` in `deeplink_for()` to the value Bring assumed (usually 4), commit,
and it re-renders. See the main README for details.
